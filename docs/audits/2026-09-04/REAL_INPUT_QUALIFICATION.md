# Real-input qualification for the read-only application

The qualification manifest records exact reviewed test-file hashes after execution. It does not certify every defensive branch. The full coverage thresholds remain enforced in `vitest.config.ts`, and CI runs the complete coverage gate after the reviewed-subset and source-review checks.

## Genuine portable inputs

- The Drinking Water Inspectorate's actual published privacy notice and GovInfo's constitutional text exercise DOCX/PDF extraction. `test/fixtures/public/provenance.json` records original URLs, rights, byte counts, hashes, and retrieval timestamps.
- NASA's actual ATom Alaska caption files exercise paired SRT/VTT parsing. Their separate provenance record contains the publication source and unmodified file hashes.
- Installed newt production translations supply actual Arabic/Hebrew text. French/Russian tests read the real locked TypeScript diagnostic catalogs. The localization subdirectory contains exact message selection, source/package hashes, attribution, and license.
- `legacy-0.1.0` contains actual flat metadata emitted by the official extracted Teleprompt0.1.0 release after importing the real repository README in an isolated profile. Every native window was closed normally before capture.
- `legacy-1.0.3` contains actual metadata and recovery draft emitted by the installed1.0.3 application. The actual editor received unmodified SECURITY.md through the native X11 clipboard; the original README source remained unchanged. The profile was closed normally before capture.

The historic profile files retain their original temporary public-source paths and authentic document identifiers. No JSON fields were rewritten. Private operator profiles and documents were not copied. Per-directory provenance identifies the application ASAR hash, input hashes, original artifact timestamps, and captured bytes.

## Executed conversion gates

The focused public-input gate passed 16 tests with no failures or skips: cue parsing 2, text statistics 5, schema 4, real X11 presentation 2, and historical recovery compatibility 3. A separate source-reviewed gate passed 17 tests across controller, workspace, concurrent crash-directory replacement, PDF budget, IPC policy, overlay projection, and metadata repositories. Parser conversion passed 7 unit cases, including its wrapper around seven real Electron utility-process scenarios.

The presentation test first failed because xev buffered stdout when connected to a pipe. Running the actual xev through `stdbuf -oL` exposed its real native event stream. The isolated presentation gate then passed 2/2, followed by the full focused 16/16 gate. Production presentation code was unchanged.

## Unexercised behavior retained as acceptance gaps

| Area | Actual evidence | Remaining gap |
|---|---|---|
| Cues | Unmodified LICENSE/SECURITY documents remain unchanged and return no cues across repeated calls. | No genuine script with valid/mixed-case, terminal, multiline/empty, overlong or more than1,000markers is available. Marker extraction, positions and safety limits require that corpus. |
| Persistence schema | Original0.1.0 migration, actual1.0.3 recovery references, current real imports, missing-state startup, and exclusion of obsolete/transient state. | No authentic incident file exercises unsafe legacy values or an unsupported future Teleprompt schema version. |
| Presentation | Actual Xvfb, focused xev window, trusted xdotool Right/Left events, and actual X server termination. | Wayland, non-Linux, unavailable xdotool, and executable-removal/spawn-error races are not reproduced by these tests. Physical desktop acceptance is tracked separately. |
| Parser supervisor | Real PDF/DOCX, actual process cancellation, stopped-process timeout, SIGKILL, RSS watchdog, and output ceiling. | The production worker validates output before emitting a response, so fabricated malformed/oversized IPC responses were removed and those defensive branches remain unexercised. RSS can overshoot the sampled watchdog threshold. |
| Structured input | Genuine DOCX/PDF, original NASA subtitles, real binary rejection and actual byte/character ceilings. | Naturally corrupted or malicious structured documents are not represented by the valid public publications. |

These gaps remain part of the six-area architectural acceptance work. Passing the file-review guard alone does not close them or justify lowering coverage thresholds.

## CI order and private artifacts

CI installs the actual X11 runtime tools, builds the application, runs packaged/native tests, and captures fresh Crashpad artifacts before the reviewed unit subset. It selects a genuine capture manifest from that run and passes it to the retention tests. Public DOCX/PDF and historical profile paths are available from the repository.

The source-review guard and full coverage gate follow these useful checks. Only JSON verification reports are uploaded by the report step; crash dumps, profiles, and traces remain on the ephemeral runner. Distributable upload steps still require the preceding gates to succeed.
